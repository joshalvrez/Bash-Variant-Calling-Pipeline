### Troubleshooting Symptoms, Causes, and Solutions:
 - During the initial stages of the project, I had initialized local variables for all functions instead of initializing global variables at the very top and referencing them whenver I need them. This caused my entire program to not only refuse to pass information from one function to the next, but it caused my entire program to fail completely at stage 0. For example, every function would start out with "local_sheet=$1" and "local_out=$2." In this scenario, $1 and $2 passed in arguments into the function but not to the script, and the driver passed none. I also found that after a leftover block of code referencing a function named "validate" instead of "stage_validate." To fix this, I had to remove the leftover block of code, since the driver loop already runs these stages. I also replaced the local variables with global ones at the top of the script. Making these changes allowed my tests to run without an issue. 

- In the very beginning stages of testing, I ran into issues with my stage 0 function where it would catch the wrong things. For example, a FASTQ file that was present but corrupt would have been reported as a "missing R1 file". I referenced the code provided during the class demo and the grading rubric for this assignment, and realized this happened because '[[ -s ]]' and 'gzip -t' were being used in one condition, so a file that existed but was corrupt got the same "missing R1 file" message as a file that wasn't there. There were also no checks in my code for a missing reference or index, or for a blank 'sample_id'. To fix this, I rebuilt stage 0 using the structure of the class demo. Checking whether a file exists and whether it is valid gzip are now separate steps, so a corrupt file gets its own message. Each check now runs on its own and adds to a 'problems' counter instead of stopping the script, so every problem is reported together at the end. I also added the missing checks for a blank 'sample_id' and for the reference and its indexes ('.fai', '.dict', '.bwt'). After the rebuild, all of the stage 0 acceptance tests passed.
